## 1. 🎯 Achado central

O scaffold **materializa as 3 fronteiras do alvo** ([`../architecture/README.md`](../architecture/README.md)
§2.1) em Electron/TypeScript — **escolha nossa (não observada no alvo)**. O **núcleo puro**
(buffer segmentado + concorrência por `worker_threads`) vive em `src/core/**`; a **ponte de
processos** (extensão/plugins e a costura `main ↔ renderer`) vira `MessagePort`/IPC tipado e
versionado; o **render** vira Canvas 2D/WebGPU com scroll virtualizado. Tudo o que atravessa
fronteira passa pelas **costuras congeladas** em `src/shared/**`, e a montagem final é o módulo de
composição `src/core/editor/**` consumido pelo `src/main/**`.

## 5. 🧵 A costura (`main ↔ core ↔ renderer`)

- **`EditorCore`** (`src/core/editor/editor-core.ts`, `createEditorCore()`) é o único que importa
  cruzado entre módulos `core`. Monta: `DocumentRegistryImpl` (buffer), `CommandBusImpl` (command),
  `SchedulerImpl`/`TaskPoolImpl` (concurrency), `PackageResolverImpl` (packages) e o
  `PropertySystemImpl` (properties). Expõe ao `main`: `openDocument`, `documentText`, `insertText`,
  `revisionOf`, `onDocumentChanged`, `snapshot()`, `dispose()`.
- **Escritor único:** as mutações passam por uma **fila de escrita** interna (`enqueue`) em torno do
  `CommandBus` — o alvo do bus é resolvido no momento da execução (`pendingHandle`/`activeHandle`),
  então `insertText` concorrentes nunca apontam para o documento errado. **Escolha nossa.**
- **Sizing pela propriedade:** `Scheduler`/`TaskPool` são dimensionados pelo `PropertySystem`
  (`editor.ioWorkers`, `index.indexWorkers`, `concurrency.maxBackgroundThreads`); o default é
  `cpus − 1` (`DEC-CON-6/9`).
- **Contrato de IPC versionado** (`src/shared/ipc-contract.ts`): envelope único multiplexado por
  `method` + `id`, eventos por nome; `IPC_VERSION = "1.0"` e o **major precisa bater** para negociar
  (`DEC-IPC-11`). O `main` (`src/main/index.ts`) registra `document.*`/`editor.snapshot`, faz
  *broadcast* de `document.changed` e assina o `FileSystem` de produção (`node:fs/promises`).
- **Renderer degrada sem ponte** (`src/renderer/main.ts`): sem `window.scribe` cai na **demo**; com
  ponte, só liga o documento real quando há `?file=`. A degradação é **explícita e logada**
  (status bar + `console.info`), nunca silenciosa (`DEC-TR-7`).
- **`electron` carregado dinamicamente** (`await import("electron")` dentro de
  `startMainProcess()`): o módulo `src/main/**` é importável em `node`/vitest porque
  `createEditorCore`, `registerIpcHandlers` e `handleIpcRequest` **não** tocam Electron. O boot só
  arranca quando `process.versions.electron !== undefined`. **Escolha nossa (testabilidade).**

| `Disposable` | um só — `shared/disposable.ts` |

| nome × opcode | superfície `"buffer.insert"`; `OPS` mapeia nome → número denso |

## 7. ▶️ Como rodar

```bash
npm install          # uma vez
npm run typecheck    # tsc --noEmit (strict)
npm test             # vitest run
npm run lint         # eslint (flat config)
npm run build        # pipeline em scripts/build.mjs → dist/
npm start            # build + electron .
npm run start:headless   # build + xvfb-run -a electron . (sem display)
```

**Pipeline de build** (`scripts/build.mjs`), 4 etapas — o porquê de não ser só `tsc`:

1. `tsc -p tsconfig.build.json` → **preserva a árvore** em `dist/` (o `TaskPool` resolve o worker por
   `path.join(__dirname, "worker-entry.js")`, então `dist/core/concurrency/worker-entry.js` precisa
   existir ao lado do resto).
2. **renderer** por **esbuild (IIFE)**: roda no Chromium como `<script src>`, onde `require` CJS não
   funciona — o bundle sobrescreve o `.js` do `tsc`.
3. **preload** por **esbuild (CJS, `electron` external)**: em `sandbox: true` o preload não pode
   `require` arquivo irmão; o bundle inlina o que vier de `src/shared/**`.
4. Cópia explícita de `index.html`/`index.css` + guarda-corpo que exige o `worker-entry.js`.

## 9. ⚠️ Limitações e pendências

- **Renderer só abre documento real com `?file=`** (`src/renderer/main.ts`); sem isso, roda a demo
  estática de 200 linhas. Digitação é mínima (1 code point por tecla).
- **`AbortSignal`/`IpcCancel` modelados, mas não fiados:** o envelope `IpcCancel`/`signalId` existe no
  contrato, mas nenhuma operação longa o consome ainda — não é exercitado ponta a ponta.
- **WebGPU não é exercitado em CI:** os testes cobrem o caminho de **indisponibilidade**
  (`WebGPUUnavailableError` → fallback declarado para Canvas2D), não a execução real do backend.
- **ZIP sem ZIP64 e sem criptografia** (`src/core/packages/zip.ts`) — pacotes de recursos além do
  caminho comum não são suportados.
- **Incógnitas da Fase 1 que ainda afetam o código** ([`../architecture/README.md`](../architecture/README.md) §6):
  `BUF-U1`/`BUF-U4` (topologia do store, cache de linha), `CON-U1`/`CON-U5` (identidade da main thread,
  coalescing do scheduler), `REN-U1`/`REN-U2` (critério de visibilidade, política de flush). As
  decisões foram tomadas mesmo assim (`DEC-*`), mas a incógnita segue aberta no alvo. `[DESCONHECIDO]`
- **Observabilidade mínima:** `MainThreadBusy` é logado em intervalo fixo; não há painel/métrica.
